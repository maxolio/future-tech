# 🎤 Тренажёр для собеседований: защита кода и архитектурных решений

Этот файл — твой конспект для подготовки к техническим интервью. Здесь собраны готовые профессиональные формулировки: как уверенно, ёмко и аргументированно объяснять свой код словами уровня Middle/Senior разработчика.

## 1. Паттерн инициализации «Коллекция и Элемент» (TabsCollection / Tabs)

### Исходный код:
```javascript
class TabsCollection {
  constructor() {
    this.init();
  }

  init() {
    document.querySelectorAll(rootSelector).forEach((element) => {
      new Tabs(element);
    });
  }
}
```

### 🟢 Версия 1: Простая и понятная (своими словами)

> «Мы создаём класс **`TabsCollection`**, который будет **управлять всеми блоками табов на странице**. 
> 
> В его конструкторе мы запускаем метод **`init()`**, который с помощью **`document.querySelectorAll`** находит в DOM все блоки табов по CSS-селектору data-атрибута (`[data-js-tabs]`). 
> 
> Затем мы проходимся по каждому найденному блоку и создаём для него независимый экземпляр класса **`Tabs(element)`**, чтобы **каждый блок жил своей жизнью и управлял строго своими кнопками и содержимым, не ломая другие табы на сайте**».

---

### 🔵 Версия 2: Профессиональная (для технического интервью / Senior-стиль)

> «Здесь реализован паттерн **Collection / Item** для масштабируемой и безопасной инициализации компонентов на странице.
>
> 1. **Назначение класса `TabsCollection`:**  
>    Этот класс выступает в роли менеджера или точки входа. Его задача — не управлять логикой конкретного таба, а найти все блоки табов в DOM-дереве и проинициализировать их, соблюдая принцип слабой связанности (Loose Coupling).
>
> 2. **Конструктор (`constructor`):**  
>    При вызове `new TabsCollection()` срабатывает метод `constructor`. По правилам чистого кода я не перегружаю конструктор тяжелой логикой, а делегирую запуск жизненного цикла специализированному методу `this.init()`.
>
> 3. **Метод `init()` и селекторы по data-атрибутам:**  
>    В методе `init` мы обращаемся к глобальному объекту `document` и с помощью метода `querySelectorAll` ищем все элементы по селектору `rootSelector` (в нашем случае это data-атрибут `[data-js-tabs]`).  
>    *Мы используем data-атрибуты вместо CSS-классов намеренно, чтобы разделить ответственность (Separation of Concerns): классы отвечают исключительно за стилизацию, а дата-атрибуты — за поведение JavaScript.*
>
> 4. **Цикл `forEach` и создание экземпляров:**  
>    Метод `querySelectorAll` возвращает NodeList, по которому мы проходимся циклом `forEach`. Для каждого найденного в разметке узла `element` мы создаём независимый экземпляр основного класса: `new Tabs(element)`.
>
> 5. **Архитектурный профит (почему это масштабируемо):**  
>    Если завтра контент-менеджер добавит на страницу второй или третий блок табов — например, в секцию с ценами или в модальное окно — нам не придётся менять ни строчки JS-кода. Каждый найденный блок получит свой изолированный экземпляр класса `Tabs` со своим собственным контекстом (`this`), своими слушателями событий и своей областью видимости кнопок. Они гарантированно не будут конфликтовать друг с другом».

## 2. Инициализация экземпляра: `this.rootElement = rootElement` и рождение объекта

### Исходный код:
```javascript
class Tabs {
  selectors = {
    root: rootSelector,
    button: '[data-js-tabs-button]',
    content: '[data-js-tabs-content]',
  };

  constructor(rootElement) {
    this.rootElement = rootElement;
    this.buttonElements = this.rootElement.querySelectorAll(this.selectors.button);
    this.contentElements = this.rootElement.querySelectorAll(this.selectors.content);
  }
}
```

### 🟢 Версия 1: Простая и понятная (своими словами)

> «Аргумент `rootElement` в круглых скобках конструктора — это временная переменная. Как только конструктор завершит работу, она сотрётся из памяти.
>
> Строчкой `this.rootElement = rootElement` мы сохраняем ссылку на переданный HTML-узел прямо в свойства самого создаваемого объекта (`this`). 
> 
> В этот момент рождается живой JavaScript-объект — персональный «пульт управления» блоком табов. Теперь любой метод класса в любой момент может обратиться к `this.rootElement` и искать кнопки не по всему сайту через `document`, а строго внутри своих стен через `this.rootElement.querySelectorAll`».

---

### 🔵 Версия 2: Профессиональная (для технического интервью / Senior-стиль)

> «Здесь мы реализуем инкапсуляцию области видимости компонента (Component Scoping):
>
> 1. **Кэширование корневого узла (`this.rootElement`):**  
>    Сохраняя переданный DOM-узел в свойство экземпляра, мы привязываем жизненный цикл DOM-элемента к контексту объекта `this`, предотвращая потерю ссылки после завершения фазы конструирования.
>
> 2. **Изолированный поиск (Scoped DOM Querying):**  
>    Вместо неэффективных глобальных выборок через `document.querySelectorAll` мы производим поиск дочерних узлов (`buttonElements`, `contentElements`) строго в поддереве корневого узла: `this.rootElement.querySelectorAll(...)`.
>
> 3. **Словарь селекторов (`selectors`):**  
>    Вынесение строк селекторов в поле класса избавляет кодовую базу от "магических строк" (Magic Strings), централизует конфигурацию и упрощает рефакторинг или изменение селекторов в одном месте».

## 3. Анатомия конструктора `Tabs`: наполнение карманов объекта инструментами

### Исходный код:
```javascript
constructor(rootElement) {
  this.rootElement = rootElement;
  this.buttonElements = this.rootElement.querySelectorAll(this.selectors.button);
  this.contentElements = this.rootElement.querySelectorAll(this.selectors.content);
  this.state = {
    activeTabIndex: [...this.buttonElements]
      .findIndex(buttonElement => buttonElement.classList.contains(this.stateClasses.isActive)),
  };
  this.limitTabIndex = this.buttonElements.length - 1;
}
```

### 🟢 Версия 1: Простая и понятная (своими словами)

> «В конструкторе мы экипируем наш живой объект `this` пятью ключевыми инструментами:
>
> 1. `this.rootElement` — сохраняем корневой узел (ключ от своей комнаты), чтобы не зависеть от временного аргумента.
> 2. `this.buttonElements` и `this.contentElements` — кэшируем коллекции кнопок и панелей контента, найденные строго внутри своего блока.
> 3. `this.state = { activeTabIndex }` — блокнот текущего состояния. Через спред `[...this.buttonElements]` превращаем NodeList в массив и методом `.findIndex` находим порядковый номер кнопки, у которой в HTML уже стоит класс `is-active`. Если активна первая кнопка — запишется `0`.
> 4. `this.limitTabIndex = length - 1` — отбойник границ. Так как индексы начинаются с `0`, для 6 кнопок максимальный индекс равен `5`. Этот лимит нужен для безопасной навигации стрелками с клавиатуры, чтобы индекс не улетал в несуществующие значения».

---

### 🔵 Версия 2: Профессиональная (для технического интервью / Senior-стиль)

> «Конструктор выполняет первичную гидратацию состояния компонента и кэширование ссылок на DOM:
>
> 1. **Кэширование DOM-коллекций:** Предотвращает повторные дорогостоящие обращения к дереву документа при последующих пользовательских взаимодействиях.
> 2. **Динамическая инициализация Single Source of Truth (`this.state`):** Мы не хардкодим индекс активного таба нулём, а динамически вычисляем его из начального серверного HTML через предикат `classList.contains(isActive)`. Это делает компонент устойчивым к изменениям начальной разметки.
> 3. **Нормализация коллекций:** Использование spread-синтаксиса `[...NodeList]` для перехода к функциональным методам массива (`findIndex`).
> 4. **Идемпотентный лимит границ (`limitTabIndex`):** Вычисление верхней границы диапазона индексов для циклической или ограниченной клавиатурной навигации (WAI-ARIA Keyboard Navigation)».
